## 手動テスト（UI操作）

### テストケース 1: 新規部門追加 → AI生成 → リロード

**目的**: 手動で追加した部門と AI 生成結果が保存・復元されることを確認

**前提条件**: Cascade ページに最低1つの部門が存在すること

**実行手順**:

1. **部門を手動追加**
   - 「+ 部門を追加」ボタンをクリック
   - 部門名を入力（例: "テスト部門"）
   - 保存ボタンをクリック

2. **AI でたたき台を生成**
   - 追加した部門の行で「AIでこの部門のたたき台」ボタンをクリック
   - ローディング完了を待つ

3. **生成結果を確認**
   ```
   期待される表示:
   - ミッション: AI が生成したテキストが表示
   - プロジェクト: 複数のプロジェクトが表示
   - 各プロジェクトに「目標（OKR）」「指標（KPI）」が表示
   ```

4. **リロード**
   - ブラウザのリロード（F5）を実行

5. **データが保持されていることを確認**
   ```
   期待される結果:
   ✓ 手動追加した部門がまだ存在する
   ✓ AI 生成したミッションが保持されている
   ✓ AI 生成したプロジェクトがまだ表示されている
   ✓ OKR/KPI データが消えていない
   ```

**失敗判定**:
- ❌ 部門が消えている
- ❌ AI 生成結果が消えている
- ❌ OKR/KPI が表示されない

---

### テストケース 2: 目標入力でKPIが増えない

**目的**: 部門の OKR 入力時に、勝手に KPI が増えないことを確認

**前提条件**: Cascade ページに部門とプロジェクトが存在すること

**実行手順**:

1. **プロジェクトの目標欄に入力**
   - プロジェクトの「目標（Objective）」欄をクリック
   - 自由に目標を入力（例: "顧客満足度を10%向上させる"）
   - Tab キーまたは別の欄をクリックして入力を確定

2. **キーリザルト（KR）欄を確認**
   ```
   期待される結果:
   ✓ KR 欄が空いたままである（勝手に補完されない）
   または
   ✓ 既に入力していた KR が上書きされていない
   ```

3. **複数の目標を入力した場合**
   - 2〜3 個の異なる目標を入力
   - 各目標について KR が勝手に増えないことを確認

**失敗判定**:
- ❌ 目標を入力すると KR が勝手に増える
- ❌ 既存の KR が上書きされている

**技術的背景**:
- TASK 3 で `sanitizeOkrsForProject` が目標 onChange から削除されました
- 目標の入力は `okrs[0].objective` を更新するだけで、KR を自動補完しません

---

### テストケース 3: lane 内訳表示（既存 / 新規の分離表示）

**目的**: 「既存進化 / 新規探索」の内訳表示が同名部門で混線しないことを確認

**前提条件**: AI 生成結果が「既存進化」「新規探索」の2レーンに分かれていること

**実行手順**:

1. **部門で AI 生成を実行**
   - 部門の「AIでこの部門のたたき台」ボタンをクリック

2. **生成内訳ボタンを探す**
   - 「生成内訳（既存 / 新規）」または「lane detail」ボタンをクリック

3. **既存 / 新規の内訳が表示される**
   ```
   期待される表示:
   - 「既存進化」セクション: X個のプロジェクト
   - 「新規探索」セクション: Y個のプロジェクト
   - 内訳の合計 = 編集画面のプロジェクト数
   ```

4. **同名部門を追加して確認**
   - 別の同名の部門を追加（例: もう一つ "テスト部門" を追加）
   - 各部門で lane detail を開く
   - 内訳が混線していないことを確認

**失敗判定**:
- ❌ 異なる部門の内訳が混ざって表示される
- ❌ lane detail が開かない

**技術的背景**:
- TASK 0 で `getDeptKey()` が導入され、同名部門でも異なるキーが割り当てられます
- `laneCacheRef` と `showLaneDetail` が `getDeptKey()` をキーとして使用します

---

### テストケース 4: 再生成で増殖しない

**目的**: 同じ部門で生成ボタンを複数回押してもプロジェクトが増殖しないことを確認

**前提条件**: 部門が存在し、既に1回以上 AI 生成済み

**実行手順**:

1. **初回生成の結果を確認**
   - プロジェクト数をメモ（例: 5個）

2. **もう一度「AIでこの部門のたたき台」ボタンをクリック**
   - ローディング完了を待つ

3. **プロジェクト数が同じことを確認**
   ```
   期待される結果:
   ✓ 初回: 5個
   ✓ 2回目: 5個（増えない）
   ```

4. **さらに3回目をクリック**
   - 同じプロジェクト数のままであることを確認

5. **プロジェクトのタイトルを確認**
   ```
   期待される結果:
   - 完全に同じタイトルは1つずつ
   - [AI#001], [AI#002] など の番号は異なるかもしれない
   - しかし正規化後のタイトルは重複しない
   ```

**失敗判定**:
- ❌ 2回目の生成でプロジェクト数が増える
- ❌ 3回目でさらに増える
- ❌ 完全に同じプロジェクトが複数存在する

**技術的背景**:
- TASK A-1: `normalizeTitleKey()` が正規化
- TASK A-2: `applyDeptDraftToProjects()` で最終 dedupe

---

### テストケース 5: 表示と編集の一致（index 不整合がない）

**目的**: プロジェクトタイトルを編集したとき、正しいプロジェクトが編集されることを確認

**前提条件**: 複数のプロジェクトが存在する部門

**実行手順**:

1. **プロジェクトのタイトルを記録**
   ```
   例:
   1. プロジェクト A
   2. プロジェクト B
   3. プロジェクト C
   ```

2. **2番目のプロジェクト（B）のタイトルを編集**
   - 「プロジェクト B」のタイトル欄をクリック
   - テキストを別のものに変更（例: "プロジェクト B - 修正版"）
   - 保存

3. **編集したプロジェクトを確認**
   ```
   期待される結果:
   ✓ 2番目のプロジェクト（元々の B の位置）のタイトルが「プロジェクト B - 修正版」に変わる
   ✓ 1番目（A）と3番目（C）は変わらない
   ```

4. **リロード**
   - ブラウザをリロード
   - 編集内容が保持されていることを確認

5. **複数プロジェクトを同時に編集**
   - 複数のプロジェクトを編集
   - 各プロジェクトが正しい行に保存されていることを確認

**失敗判定**:
- ❌ 別のプロジェクト（1番目や3番目）が変わる
- ❌ 編集内容が反映されない
- ❌ リロード後にデータが失われる

**技術的背景**:
- TASK 1: `deptProjects = (dept.projects as Project[] | undefined) ?? []` で一次ソースを `dept.projects` に統一
- `laneCacheRef` は参考表示のみで、編集に影響しません

## トラブルシューティング

### 問題: 自動テストで「API呼び出しエラー」が出る

**原因**: 開発サーバーが起動していない

**対策**:
```bash
npm run dev
```

別ターミナルでこのコマンドを実行して、サーバーが起動するまで待つ

---

### 問題: AI 生成ボタンをクリックしても何も起きない

**原因**: API エラーか、デバッグログを確認する必要がある

**対策**:
1. ブラウザの DevTools（F12）を開く
2. Console タブを確認
3. エラーメッセージを確認

---

### 問題: 編集後、保存ボタンが押せない

**原因**: immutable 更新の影響か、state が正しく更新されていない可能性

**対策**:
1. ブラウザの DevTools → Redux DevTools が利用可能であれば確認
2. `dispatch(pushToStore(updatedDepartments))` が正しく実行されているか確認
3. `jsonEq()` で差分検知が正しく動作しているか確認

---

### 問題: リロード後、データが消える

**原因**: Hydration タイミングが不適切か、lastServerSnapshot が NULL のまま

**対策**:
1. ブラウザのローカルストレージを確認（DevTools → Application → Local Storage）
2. DB から正しくロードされているか確認
3. boot?.isHydrated が true になるまで待つ

---

### 問題: 同名部門でlane detailが混線する

**原因**: getDeptKey() がまだ index に基づいていない可能性

**対策**:
```typescript
// page.tsx 行 1403-1416 を確認
const getDeptKey = useCallback((dept: Department, index: number): string => {
  if (dept.id) return String(dept.id);
  const fallbackKey = `${accessCompanyId}::${dept.name}::${index}`;  // ★ index が含まれているか
  if (!deptKeyRef.current[fallbackKey]) {
    deptKeyRef.current[fallbackKey] = crypto.randomUUID();
  }
  return deptKeyRef.current[fallbackKey];
}, [accessCompanyId]);
```
