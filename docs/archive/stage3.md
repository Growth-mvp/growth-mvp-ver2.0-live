# Stage 3: 部門戦略策定（カスケード）

## 目的
Stage 2 で確定した「統合戦略ストーリー／勝ち筋」を、部門単位のミッション・プロジェクト・OKR に展開します。  
全社戦略 → 部門 → プロジェクト → OKR の一貫性をつくり、以降の実行（Stage 4/5）とシミュレーション（Stage 6）に接続できる“行動の設計図”を完成させます。

## ユーザーがやること（最小）
1. **部門を整備**：実組織に合わせて部門を用意（追加/削除は権限により制御される場合があります）
2. **部門ミッションを作る**：全社戦略のどの要素を担当するかを明文化
3. **プロジェクトを定義**：部門ミッションを実現するための主要プロジェクト（目安 2〜4本）
4. **OKR を作る**：各プロジェクトに Objective / Key Results（必要に応じて Owner）を設定
5. **整合性を確認**：上位戦略（Stage 2）と下位（部門OKR）が矛盾していないかをチェックして修正

## 画面・入力の考え方（UI創作を避けた公式説明）
- Stage 3 は「カスケード（階層）」として、**部門 → プロジェクト → OKR** を編集・確認します。  
- 画面上の具体的な名称（タブ名、ボタン名、パネル構成）は実装・リリース状況で変わるため、**ここでは“やるべき入力の単位”で説明**します。

### 入力単位 1：部門
- **部門名**（例：営業、製造、企画、人事 など）
- **部門ミッション**（Stage 2 の戦略ストーリー／勝ち筋の「どこを担当するか」を一文で）

### 入力単位 2：プロジェクト
- **プロジェクト名**（例：価格改定、DX基盤構築、新商品開発 など）
- プロジェクトは「部門ミッションを実現する主要な活動のまとまり」として定義します  
  ※目的・期間・メタ情報などは、画面にある入力項目に合わせて必要範囲で定義します（未実装の項目を断言しません）

### 入力単位 3：OKR（プロジェクトごと）
- **Objective**：定性的な“目指す状態”（50〜150字目安）
- **Key Results**：定量的な“成功基準”（3〜5個目安）
- **Owner**：責任者（画面に項目がある場合のみ設定）

## AIサポート（存在する範囲で）
- 部門ミッションやプロジェクト案、OKR のたたき台は **AI 支援で生成・編集**できます。
- さらに、必要に応じて **掘り下げ質問（ステップ形式）**で「整合性・納得感・協働性」などを深掘りし、回答を蓄積できます。  
  ※AI支援の呼び方や配置は実装で変わるため、UI名は断言しません。

## 出力（Stage 3で得られる成果）
- **部門別の戦略カスケード**（全社戦略 → 部門ミッション → プロジェクト → OKR）
- **実行へ渡せるOKRセット**（Stage 4/5 の実行計画・運用に接続可能な状態）

## よくある詰まり（対処）
### 「部門ミッションが全社戦略と結びつかない」
- 対処：部門ミッションの末尾に「戦略要素（勝ち筋）のどれを担当するか」を1つ書き添えます。  
  例：「新規獲得の勝ち筋を、営業の再現性として実装する」

### 「プロジェクトが多すぎてOKRに落ちない」
- 対処：年度内に“やり切れる”本数（2〜4本）に絞り、残りは後続候補として扱います。

### 「KRが定量化できない」
- 対処：KRは“測れる指標”に寄せます（数・率・時間・単価・件数・歩留まり等）。  
  例：×「品質を上げる」→ ○「不良率を 2.0% → 1.0% に改善」

### 「上位と下位の整合が不安」
- 対処：CEOChat（advisor/facilitator）で、次の形式で確認すると精度が上がります：  
  - 「この部門ミッション／OKRは、Stage2の勝ち筋のどこに効いている？ズレがあれば指摘して」
