# Stage 5: 実行支援

## 目的
Stage 4で策定した実行計画を、定期的な進捗入力とレビューで「回し続ける」ための運用ステージです。  
プロジェクト／OKRの進捗を可視化し、必要に応じてAIが要点整理・次アクション提案を行い、実行の停滞や手戻りを早期に減らします。

## ユーザーがやること（最小）
1. **進捗を定期入力**（週次または月次）
2. **遅れ・リスク・詰まりを記録**（短くて良い）
3. **次の一手を決める**（次回までにやる最小アクション）
4. （必要に応じて）**AIに要約・示唆を依頼**（状況整理／次アクションの言語化）

## 進捗入力で扱う情報（UI名に依存しない公式説明）
- **達成度（%）**：現在の進み具合（目安でOK）
- **直近の進展**：前回から何が進んだか（1〜3行）
- **課題・リスク**：詰まり／遅れの原因（あれば）
- **次アクション**：次回までにやる最小の一手（1〜3個）
- （任意）成果物リンク：資料・ドキュメントがある場合のみ

※「マイルストーン」「ステータス（On Track等）」「特定のボタン名」などは、実装状況で差が出るため**断言しません**。  
ナレッジ（docs）に明記された概念だけを前提にします。

## AIサポート（できることの範囲を限定して説明）
- 進捗入力や過去ログを材料に、以下を支援できます：
  - **要点要約**（いま何が論点か）
  - **リスクの言語化**（何が遅れ要因か／どこが不確実か）
  - **次アクション提案**（最小の打ち手を最大3つ）
  - **上位戦略との整合チェック**（Stage2/3とのズレの指摘：必要時）

※「自動で学習して精度が上がる」等の挙動は、仕組みとして実装されていない限り断言しません。  
（現状は、保存されている戦略データとログを“入力”として使う、という設計が基本です。）

## 出力（Stage 5で得られる成果）
- **進捗ログ**：プロジェクト／OKRごとの履歴（入力が積み上がる）
- **実行の見える化**：どこが進み、どこが止まっているかが分かる状態
- **レビュー材料**：月次・四半期で意思決定できる最低限の材料

## よくある詰まり（対処）
### 「入力頻度が分からない」
- 目安：**週1**（短期は週2、長期は月1でも可）
- 重要なのは“頻度”よりも、**毎回「次アクション」を固定して残すこと**です。

### 「課題が多すぎる」
- 対処：まずは**今週止めている1〜2個**だけを書く（全部を書かない）。
- AIに「今週の最小ボトルネックを1つに絞って」と依頼すると整理しやすいです。

### 「AIが汎用的になる」
- 対処：進捗入力に **数字（%）** と **詰まり原因（具体）** と **期限** を1つ入れるだけで改善します。  
  例：×「忙しい」→ ○「担当者が2人欠員で、検証が1週間遅延」
