## 📊 現状分析

### 発見事項

| 項目 | 現状 | 問題 |
|------|------|------|
| **Department.id** | ❌ 生成されない | Dry-run で 7個全て missing |
| **Project.id** | 🟡 Frontend のみで生成 | `genIdByTitle()` で生成、DB 復帰時に失われる |
| **Lanes 構造** | ✅ API で生成 | Store には保存されない（実装上の注記あり） |
| **ID の再現性** | 🟡 部分的 | Project は deterministic ですが再 restore で失われる |
| **Normalize 時** | ❌ ID 生成なし | `normalize.ts` では id を補完しない |

### Root Cause

1. **API 生成時** (`generate-cascade/route.ts`)
   - Department は lanes 構造を持つが、department.id は生成されない
   - Project は lanes 内で生成されるが、project.id は AI で生成されない

2. **Frontend 処理時** (`cascade/page.tsx`)
   - `normalizeProjectDraft()` で project.id = `genIdByTitle(deptName + title)` を付与
   - **ただし lanes.existing/new の project には処理が及ばない可能性**
   - Department の id は生成されない

3. **保存時** (`saveStrategyData`)
   - Payload には既に id が無い場合がある
   - Normalize を通す際に id 補完ロジックがない

4. **復帰時** (`normalizeDepartmentsAny`)
   - Lanes 構造は normalize.ts で復帰される ✅
   - ただし id は「あれば保持、無ければ undefined のまま」

## 🎯 実装方針

### A. 新規生成時の stable id 付与

**タイミング**: API 生成後（frontend で normalize する時点）

**対象**:
- lanes.existing.projects[] の各 project
- lanes.new.projects[] の各 project
- 新規作成された department

**方法**: 既存の `genIdByTitle()` を拡張
- Department id: `genIdFromName(strategyId + deptName)`
- Project id: `genIdFromName(strategyId + deptName + laneType + title)`
  - laneType: "existing" | "new" で衝突回避

### B. 既存データ復帰時の stable id 補完

**タイミング**: DB から restore → normalize.ts を通る時点

**対象**:
- Department に id がなければ補完
- Project に id がなければ補完

**方法**: deterministic generation
- 同じ strategy_id, deptName, lane, title から常に同じ id を生成
- 毎回ランダムではなく、seed ベースの hash

**制約**:
- Restore のたびに変わらないこと
- 既存データに後付けで id を補完しても一貫性が保たれること

## 🔄 Stable ID の生成ルール

### Department ID

```
Seed = strategy_id + "::dept::" + department.name
ID = hash(Seed) → "dept-{hexValue}"

例:
  Seed: "f0c22d71-96a5...::dept::営業部"
  ID:   "dept-a1b2c3d4"
```

### Project ID

```
Seed = strategy_id + "::proj::" + department.name + "::" + lane_type + "::" + project.title
ID = hash(Seed) → "proj-{hexValue}"

例:
  Seed: "f0c22d71-96a5...::proj::営業部::existing::既存顧客の深耕"
  ID:   "proj-e5f6g7h8"
```

### Hash 関数

```typescript
// Deterministic hash (same seed → same output always)
function hashFromSeed(seed: string): string {
  let hash = 0;
  for (let i = 0; i < seed.length; i++) {
    const char = seed.charCodeAt(i);
    hash = ((hash << 5) - hash) + char;
    hash = hash & hash;  // 32-bit integer
  }
  return Math.abs(hash).toString(16).padStart(8, '0');
}
```

**保証**:
- ✅ Same seed → Always same output
- ✅ Restore 後も同じ id を生成
- ✅ No gen_random_uuid() fallback
- ✅ Deterministic and reproducible

## 🔧 ID 付与タイミング

### タイムライン

```
1. AI 生成（API）
   ├─ department は lanes を返す（id なし）
   ├─ project は lanes.existing/new に配置（id なし）
   └─ →  API response に id がない状態

2. Frontend 処理（cascade/page.tsx）
   ├─ normalizeProjectDraft() を通す
   ├─ ★ HERE: department.id を `generateDepartmentId()` で付与
   ├─ ★ HERE: lanes.existing.projects[].id を `generateProjectId(..., 'existing')` で付与
   ├─ ★ HERE: lanes.new.projects[].id を `generateProjectId(..., 'new')` で付与
   └─ →  Full id がある状態

3. Store に保存（store/strategyStore.ts）
   ├─ sanitizeDepartments() を通す
   ├─ ★ ダブルチェック: id がなければ補完
   └─ →  Store に id がある状態で入る

4. DB に保存（utils/supabase/strategy.ts）
   ├─ saveStrategyData() 実行前に id を確認
   ├─ ★ Payload に id がなければ补完（failsafe）
   └─ →  DB に id がある状態で保存

5. DB から復帰（normalize.ts）
   ├─ normalizeDepartment() で id を保持
   ├─ normalizeProject() で id を保持
   ├─ ★ ない場合は generateXxxId() で补完
   └─ →  Restore 後も id がある状態
```

## ✅ Lanes 構造への対応

**重要**: lanes.existing と lanes.new の両方で project.id を付与する

```typescript
// Before:
lanes: {
  existing: { projects: [{ title: "...", okrs: [] }] },
  new: { projects: [{ title: "...", okrs: [] }] }
}

// After:
lanes: {
  existing: { projects: [{ id: "proj-xxx", title: "...", okrs: [] }] },
  new: { projects: [{ id: "proj-yyy", title: "...", okrs: [] }] }
}
```

**Lane type を seed に含める理由**:
- 同じ department/title でも lane が異なれば別 project
- existingとnewで同じ title でも衝突しない
- Seed: `strategyId::proj::deptName::new::title`
