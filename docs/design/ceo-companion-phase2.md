# AI経営コンサルタント 自律伴走の設計（PHASE 1・2 実装後）

## 1. 目的と範囲

AI経営コンサルタントが、利用者の次の一歩（操作・進行）と、節目の経営助言を、重複や過剰な呼び出しなしに届ける。

- 操作支援：今の画面で何をどう操作するか（操作登録簿の手順に限る）。
- 進行支援：次に何を進めるとよいか、その理由（プログラムで判定）。
- 経営支援：分析完了・戦略生成・戦略確定の節目での助言（AIが保存済みの内容から書く）。

範囲外：STAGE0〜6、DB、RLS、共通store、保存処理、財務計算ロジックの変更。AIによる戦略・計画データの自動変更。

## 2. 基本方針

1. 操作と進行の判定はプログラムで行う。AIは節目の助言だけを担う。
2. 保存済みの内容だけを判定と助言の材料にする。未保存の変更がある間は判定も助言の依頼もしない。
3. 判定できない状態（読み込み中、取得失敗、会社切替中）は「未入力」と断定しない。
4. AIを呼ぶのは節目ごとに一度だけ。同じ内容では二度と依頼しない。1日の依頼は2件まで。
5. 会社・利用者ごとに履歴を分ける。
6. 既定はOFF（利用者が設定で有効にする）。環境変数 `NEXT_PUBLIC_CEO_COMPANION_DISABLED=true` で全体を止められる。

## 4. 進行と操作の判定

判定の順序（先に該当したものを出す）：

1. 未保存の変更（SAVE_PENDING）：保存を先に案内する
2. 会社名（ENTER_COMPANY_NAME）→ 財務（ENTER_FINANCE）→ 論点（ADD_ISSUE）
3. STAGE2（GO_STAGE2 → STAGE2_GENERATE → STAGE2_CONFIRM）
4. STAGE3（STAGE3_ADD_DEPARTMENT → STAGE3_PROJECT）
5. STAGE4（STAGE4_PLAN）

編集権限がない利用者には「編集は管理者・管理職が行います」と添える。

## 5. 節目の経営助言

- 節目は保存済みの内容から検出する：`ANALYSIS`（論点が保存された）、`GENERATE`（経営戦略が生成された）、`CONFIRM`（経営戦略が確定された）。新しい節目を優先する。
- 節目の鍵は `MILESTONE:<節目>:<会社>:<戦略>:<内容の指紋>`。同じ鍵では一度だけ依頼する（失敗しても再依頼しない）。
- 1日の依頼は `COMPANION_MAX_ADVICE_PER_DAY`（2件）まで。
- 依頼の文と規則は、事実と仮説を分け、根拠のない数値を作らず、判断は利用者に委ねる内容にする。注目の観点は、顧客が選ぶ理由、未解決課題と勝ち筋、全社と部門の戦略の整合、部門間のすり合わせ、目的と手段、社員の主体的な判断。
- 助言の本文は、このタブの中（sessionStorage）だけに保存する。再読み込みでも再依頼せず表示する。

## 6. 表示の制御

- 進行の案内：同じ日に同じ案内は出さない。未完了の作業は翌日に再び案内する。
- 案内は画面内に見えた時に「表示済み」として記録する（引き出しが閉じたままでは記録しない）。
- 1セッションで出す案内は最大3件、案内の間隔は60秒（助言は間隔の制限を受けない）。
- 間隔で見送った案内は、間隔が過ぎた後に判断し直す。

## 7. 会社と利用者の分離

- 保存先の鍵はすべて利用者と会社で分ける。
- 会社が切り替わると、表示中の案内と助言の状態を消す。
- 助言の応答が届いた時点で会社が変わっていれば、表示も保存もしない。
- 判定は、画面の会社と保存データの会社が一致し、読み込みが完了している時だけ行う。

## 8. 保存する情報（端末のみ）

| 保存先 | 鍵 | 内容 |
|---|---|---|
| localStorage | `growth.ceoCompanion.pref.v1:<利用者>` | 伴走のON/OFF |
| localStorage | `growth.ceoCompanion.days.v1:<利用者>:<会社>` | 案内を見た日（案内の鍵ごと） |
| localStorage | `growth.ceoCompanion.advice.v1:<利用者>:<会社>` | 依頼済みの節目 |
| localStorage | `growth.ceoCompanion.advice.v1:<利用者>:<会社>:day` | 助言の依頼の日付と件数 |
| sessionStorage | `growth.ceoCompanion.session.v1:<利用者>:<会社>` | このタブの案内の件数と最後の時刻 |
| sessionStorage | `growth.ceoCompanion.adviceText.v1:<利用者>:<会社>` | 助言の本文（このタブだけ） |

会話本文は保存しない。

## 9. 検証状況

- 単体テスト（Jest）：判定、節目、表示の上限、同じ日の抑止、会社の分離、助言の上限、助言の失敗と再依頼、処理中の会社切替（助言が表示も保存もされないこと）。
- 実ブラウザ（モックのAI応答、実データの読み取り）：未保存の表示、節目の助言の1回依頼と再読み込み後の表示、翌日の再案内、同じ日の抑止（案内を見た後）、手動チャットの併存、チャットの失敗時の表示、STAGE0〜6の表示。
- 実ブラウザで未確認：会社切替の実操作（複数会社のアカウントが必要）、助言APIの失敗時の表示（節目を作るには保存データの変更が必要）。これらはJestで確認している。

## 10. 残課題

- 助言の依頼は、失敗しても自動では再試行しない（同じ節目の二重依頼を防ぐため）。
- 助言は保存済みの内容だけが対象のため、未保存の作業中は助言されない。
- 検証用の会社が無いため、STAGE5・6の情報は本文書の範囲外（PHASE 3で扱う）。
