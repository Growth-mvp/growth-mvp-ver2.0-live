# AI経営コンサルタント PHASE 2 設計（自律伴走の拡張）

## 1. 目的と範囲

PHASE 1（STAGE1→STAGE2の案内）を、STAGE1〜4全体と、経営判断を支える支援に広げる。

- STAGE1〜4の操作案内を、保存済みデータの状態に応じて自律的に出す。
- 経営情報に基づく助言（財務の見通し、達成率、資金の余力）を、既存の計算結果から行う。
- 戦略の批判的検証（前提と根拠の矛盾を指摘する）を行う。
- 経営判断の材料を整理する（選択肢、前提、トレードオフ）。判断は利用者が行う。
- 部門間の議論を支援する（STAGE3の調整候補とSTAGE4の計画の食い違いを論点にする）。

範囲外：既存のSTAGE画面、DB、共通store、保存処理、財務計算ロジックの変更。AIによる戦略・計画データの自動変更。

## 2. 基本方針（PHASE 1 から継承）

1. 状態の判定はプログラムで行う。AIは説明と助言を担う。
2. 判定できない情報は「未入力」と断定しない（読み込み中・失敗・会社切替中は判定しない）。
3. AIを呼ぶのは、利用者が求めた時、または明示的に選んだ時だけ。自動の定期呼び出しはしない。
4. 会社・利用者ごとに履歴を分ける。案内の重複は「状態が変わった時」と「同じ日」の単位で抑える。
5. 自律伴走は既定OFF。利用者が設定で有効にする。環境変数で全体を止められる。
6. 出力は「事実 / 計画 / 推計 / 仮説」と「登録済み / 未登録 / 未算定 / 未参照」を区別する（既存の回答規約に従う）。

| 要素 | 役割 | 既存資産 | 新設 |

## 4. 機能の設計

### 4.1 STAGE1〜4の操作案内（自律）
- 状態判定の順序：STAGE1（会社名、財務、論点）→ STAGE2（戦略議論、最終確定）→ STAGE3（たたき台、6問、採否、確定）→ STAGE4（計画、財務効果、実行開始）。
- 次の一歩は、登録簿の操作（`operationId`）に紐づける。登録簿にない操作は案内しない。
- 作業の途中（例：STAGE3で採否が未保存）は、保存されていないことを先に示す。

### 4.2 経営情報に基づく助言
- 材料：`buildStage6PlanBlock` が返す年度別の見通し、達成率、資金不足の判定、STAGE4の計画ブロック。
- 新しい計算はしない。既存の計算結果の一部を、利用者の質問に応じて渡す。
- 未算定・未登録の項目は、助言の前提として「不足している」と明示する。

### 4.3 戦略の批判的検証
検証は決定的なルールで行い、AIは説明する。初期のルール候補：

- 目標の矛盾：経営目標（STAGE2）の年度が、見通しの予測期間の外にある。
- 施策効果の根拠不足：確認済みでない財務効果が、戦略の根拠として使われている（STAGE4）。
- KPIの未設定：目標値または期限・担当が未入力のKPIがある（STAGE4）。
- 部門の不整合：STAGE3の採用された施策が、STAGE4の計画に存在しない。
- 数値の単位：単位の確認が必要な値がある（既存の単位警告を流用）。

各検証結果には、根拠（どの画面の、どの値か）を付ける。根拠のない指摘は出さない。

### 4.4 経営判断の材料
- 判断の対象（例：この施策を計画に入れるか）について、選択肢、各選択肢の前提、既存の数値への影響を整理する。
- 推奨は出さない。前提が「仮説」の場合は、その旨を明記する。
- 判断の記録は、この段階では保存しない（PHASE 3で検討）。

### 4.5 部門間の議論
- 材料：STAGE3の調整候補（採用・不採用の状態）と、STAGE4の計画（部門ごとのKPIと投資）。
- 論点は「部門A と 部門B が同じ顧客・資源を取り合っている」など、データで確認できるものに限る。
- 議論の進め方（論点の順序、各部門への確認事項）を提示する。決定はしない。

## 5. 安全設計

- 自動変更なし：案内、検証、判断材料は表示のみ。保存・更新の操作は利用者の操作に限る。
- AIの呼び出し回数：利用者の操作1回につき最大1回。定期の自動呼び出しはしない。
- 会社分離：案内の履歴、検証の結果、AIへの送信内容は会社ごとに分ける。切替中は判定しない。
- 権限：編集権限がない利用者には、編集を伴う操作の案内に「管理者・管理職が行う」と明記する。閲覧できない情報は、材料に含めない。
- 個人情報：組織変革ルームの個人の違和感は、共有範囲の外に出さない（既存の規則に従う）。
- AI停止時：案内と検証は、AIなしで動く（PHASE 1 の性質を維持）。

## 6. 既存機能への影響

- STAGE1〜6、組織変革ルーム、経営計画書：読み取りのみ。UIの変更は、自律伴走の表示領域（CEOChatPanel）に限る。
- 手動チャット：既存の送信処理をそのまま使う。自律伴走の案内は会話履歴に入れない（PHASE 1 の方針を継続）。
- 既存の回答品質：経営情報の助言は、既存のブロック（`stage6Plan` など）を流用するため、既存の回答の材料を変えない。

## 7. 段階的な実装計画

- PHASE 2a：STAGE3・4の状態判定と操作案内（決定的な判定のみ、AIなし）。
- PHASE 2b：戦略の検証ルール（4.3）と、根拠の表示。
- PHASE 2c：経営判断の材料（4.4）。AIへの相談は手動のみ。
- PHASE 2d：部門間の議論の論点（4.5）。

各段階で、AIを使わない部分の単体テストと、実ブラウザでの確認を行う。実ブラウザ確認には、検証用の会社（STAGE1〜4の状態が分かれているもの）が必要。

## 8. 未決定事項（利用者への確認）

1. 検証用の会社（テスト用アカウント、または検証用データ）を用意できるか。PHASE 1 の実ブラウザ確認の残りと、PHASE 2 の全段階で必要になる。
2. 検証の結果や判断の材料を、利用者の端末に残すか（PHASE 1 は端末の記録のみ）。
3. AIへの相談の回数に上限を設けるか（費用の見積もりに影響する）。
4. 部門間の議論で扱う部門の範囲（全部門か、利用者が選んだ部門か）。

## 9. テスト方針

- 判定ルール：入力状態の組み合わせごとの単体テスト（PHASE 1 と同じ形）。
- 検証ルール：根拠のない指摘が出ないことを確かめるテスト（根拠の欠落を検出する）。
- 安全性：AI停止、会社切替、読み込み中の判定停止の統合テスト。
- 既存機能：既存のSTAGE・チャットのテストが引き続き通ること。
