**出典**: `design-docs/3-stakeholder-plan-detailed-design.md`（[docs/archive/stakeholder-plan-dev-2026-10/](../archive/stakeholder-plan-dev-2026-10/) に保存）。現行の要点は [STAKEHOLDER_PLAN_DESIGN.md](STAKEHOLDER_PLAN_DESIGN.md) と [spec/10](../spec/10-stakeholder-plans.md) を参照。

## 1. 章構成（設計案）

実装（生成プロンプト）は 3 種類とも 5 章。設計案との差は [STAKEHOLDER_PLAN_DESIGN.md](STAKEHOLDER_PLAN_DESIGN.md) §9 に記録している。

- **銀行向け（設計案 7 章）**: 1 課題と分析（1.1〜1.4）、2 改善戦略（2.1〜2.3）、3 実行計画（3.1〜3.3）、4 財務予測とキャッシュフロー（4.1〜4.3）、5 返済計画（DSCR を含む。5.1〜5.3）、6 リスクと前提（6.1〜6.3）、7 融資判定（7.1〜7.3）。付録として CFO 署名のページ（未実装）
- **株主向け（設計案 6 章）**: 1 環境と方向性、2 中期方針（KPI、ポートフォリオ）、3 事業別の実行（3.3 M&A を含む）、4 財務目標とシナリオ、5 株主価値（ROE・ROIC、配当・EPS）、6 リスク。表紙の「2024-2026」は古い
- **社員向け（設計案 5 章）**: 1 方針（MVV、CEO メッセージ）、2 全社目標（3〜5 項目）、3 部門計画（部門 OKR）、4 個人の目標と育成（カスケード OKR、メンター）、5 実行と進捗。個人の欄はプレースホルダ

## 2. 画面の操作一覧（案・未実装）

承認（銀行のみ）、分類ラベル、版の表示、出力形式の切り替えを想定していた。現行の実装には承認・版管理の UI はない。

## 3. 本文の状態表示（案）

「準備中」「入力待機」の文言と、サンプルの日付・数値（元の資料 minimum-prototype-plan L183-227）。サンプルの日付は古く（2024 年・3 月末）、そのままでは使わない。

## 4. 数値検証ルール（案・未実装）

- STAGE4 と STAGE6 の差は ±15% 以内（設計案 L678）
- 部門の売上の合計は、全社の売上の 1.05 倍以下（L679）
- 月次の合計と年次の差は ±5% 以内（L680）
- 営業キャッシュフローは利払い以上（L681）
- 確信度の合計は 1.0 以下（L683）
- 検証 API `/api/validate/plan-consistency`（L414、L431）: リポジトリに存在しない。未実装

## 5. 性能目標（未計測）

API は 3 秒以内。PDF は 50 ページ 10 秒以内、100 ページ 20 秒以内。100 ページ時のメモリ 500MB 以内。DB クエリは 1 秒以内（L656-662）。

## 6. リスクと対策（案）

| リスク | 対策（案） |
|---|---|
| STAGE6 のデータが無い | 不足情報のルールに従って表示する |
| AI の品質 | 根拠が示せない箇所を明示する |
| 大きな PDF の失敗 | html2canvas の制限を踏まえた実装、または軽量版 |
| 他社データの混入 | RLS の二重確認と監査ログの監視 |
| 性能 | 性能目標の計測 |
| 利用者の混乱 | 画面の説明 |

（元の資料 L691-698）
