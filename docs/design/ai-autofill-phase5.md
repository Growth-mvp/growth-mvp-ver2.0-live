# AI自動入力・操作代行 設計（PHASE 5：5A 仕上げ・5B）

## 1. 目的と入口

AI経営コンサルタントへの自然言語の依頼（例：「日本製罐の基本情報を入力して」「証券コード5905の財務データを取り込んで」）を入口に、
公開資料（EDINET の有価証券報告書の構造化データ）から基本情報と5期の財務を候補にし、
利用者の承認後に既存の入力処理で反映する。AIは依頼の読み取りに使わず（判定は決定的）、数値の取得と照合はプログラムが行う。
手動入力は従来どおり残す。

## 2. 実装範囲と状況

| 項目 | 状況 |
|---|---|
| 依頼の入口（AI経営コンサルタントのチャット） | 実装済み。依頼と判定されたら、AIを呼ばずに候補を作り、STAGE1の承認欄へ渡す |
| 会社名・証券コードから、証券コード・EDINETコードを特定 | 実装済み。実データで確認（日本製罐・丹青社） |
| 提出日の範囲をシステムが決める | 実装済み（後述） |
| 企業基本情報（会社名・証券コード・上場・決算月・所在地・従業員数・事業内容） | 実装済み。実データで照合 |
| 業種 | **未取得**（構造化データに東証33業種が無い）。推測せず、未入力のまま |
| 事業セグメント（名称・金額） | **未取得**（説明文は取れるが、名称と金額を構造化して取り出せていない）。未入力のまま |
| 直近5期の通期 PL（売上高・親会社株主に帰属する当期純利益） | 実装済み。5期分が書類にある |
| 直近5期の通期 PL（営業利益） | 書類の連結財務諸表にある**2期（前期・当期）のみ**。他の年度は未取得のまま |

| 決算年度・連結・単体・通貨・金額単位・訂正報告書 | 実装済み（後述の確認を行う） |
| 承認後の一括反映（既存の入力処理） | 実装済み。`setProfile`・`setFinancePL`・`setFinanceBS`（既存のsetter）のみ |
| 手動入力 | 残している（変更なし） |

## 4. 提出日の範囲（システムが決める）

- 上場企業の有価証券報告書は、決算月に応じて提出時期が集中する（3月決算は6月、12月決算は3月、1月決算は4月、など）。
- 会社の決算月は特定の前は分からないため、提出が集中する月を優先順に読む：6月、3月、4月、9月、12月、7月、10月、1月、2月、5月、8月、11月。
  各月は直近の該当期間のみ。今日より後は読まない。土日は読まない。1日1回。
- 有価証券報告書が見つかったら、その提出後45日の範囲で、同じ期の訂正報告書（書類種別 130）を確認してから止める。
- 読み取りの上限：150日（超えたら途中で止め、証券コードでの指定を求める）。
- 実測（2026-11-19、実データ）：日本製罐は54日（6月の窓で発見）、丹青社は99日（6月・3月は見つからず、4月で発見）。

## 5. 原資料との照合（実データ）

対象：日本製罐株式会社（証券コード 5905、EDINET E01408、有価証券報告書 S100YK2J、第121期 2025/04/01〜2026/03/31）、
株式会社丹青社（証券コード 9743、EDINET E00208、有価証券報告書 S100Y04L、第68期 2025/02/01〜2026/01/31）。
取得元は EDINET の構造化データ（CSV）。値は書類の記載をそのまま使い、推測はしていない。

| 確認項目 | 日本製罐 | 丹青社 |
|---|---|---|
| 会社名（表紙・DEI） | 一致 | 一致 |
| 本店所在地 | 埼玉県さいたま市北区吉野町２丁目275番地 | 東京都港区港南１丁目２番70号 |
| 上場市場 | 東京証券取引所スタンダード市場 | 東京証券取引所プライム市場 |
| 決算月 | 3（期末 2026-03-31） | 1（期末 2026-01-31） |
| 従業員数（当期末） | 189 | 1,579 |
| 売上高（当期） | 11,442,246,000円 | 107,222,000,000円 |
| 営業利益（当期） | △307,863,000円 | 8,358,000,000円 |
| 親会社株主に帰属する当期純利益（当期） | △346,736,000円 | 5,993,000,000円 |
| 総資産（当期末） | 12,975,874,000円 | 55,725,000,000円 |
| 純資産（当期末） | 4,856,436,000円 | 37,665,000,000円 |
| 主要指標（5期）と連結財務諸表（当期・前期）の照合 | 全件一致（9組） | 全件一致 |

照合の方法：5期の主要指標（書類の経営指標の表）と、連結財務諸表（当期・前期）を同じ年度で比べ、
すべて一致した時だけ「連結」として採用する。一致しなければ、数値は採用せず、「照合が取れない」と示す。
試験では、わざと値を変えた場合に採用されないことも確認している。

## 6. 確認事項（厳格に）

- **決算年度**：期末日から年度を決め、候補ごとに持つ。
- **連結・単体**：主要指標と連結財務諸表の照合で確定。従業員数は書類の要素だけでは連結・単体を確定できないため「未確認」。
- **通貨・単位**：CSV の単位が「円」の値だけ採用。「円」でない値は除外して、その旨を示す。
- **訂正報告書**：同じ期の訂正報告書がある時は、その値を採用し、元の書類との関係を示す。
- **取得できない項目**：推測で補わない。未取得の項目は、承認欄と反映結果に明示する。

## 7. 安全設計

- **承認前は反映しない。** 候補の取得・チャットの依頼では、入力欄（ストア）を変えない。反映は「承認して反映」の押下時のみ。
- **既存データを無断で上書きしない。** 入力済みの項目・年度は、利用者が上書きを選んだ時だけ変える。
- **企業ID・戦略ID・権限。** 取得時にサーバーで所属・役割（manager以上）・戦略と会社の対応を確認。反映時に画面の企業と戦略が取得時と同じかを確認し、違えば反映しない。
- **AIに任意のコードやAPIを実行させない。** 公開資料の取得先は EDINET に固定。AIは依頼の入口でのみ使い、数値には関与しない（現行の判定は AI を使わない）。
- **DB・RLS・共通store・保存処理・財務計算は変更しない。** 反映は既存の setter（`setProfile` `setFinancePL` `setFinanceBS`）のみ。保存は既存の自動保存。
- **停止手段。** `NEXT_PUBLIC_STAGE1_AUTOFILL_DISABLED=true` で、承認欄を隠し、依頼の入口も 503 を返す。
- **APIキーの扱い。** 鍵は環境変数 `EDINET_API_KEY` にのみ置き、応答・ログ・画面に出さない（ログは状態コードのみ）。
- **外部への問い合わせ。** 429 などの失敗では再試行しない。読み取りの上限を設ける。
- **監査。** 候補の作成は、会社・利用者・書類ID・読み取った日数を監査ログに残す（本番の監査テーブルへの書き込み。試験では監査は模擬している）。

## 8. 試験

- 抽出：日本製罐・丹青社の実データ（最小の行だけ抜き出した試験データ）で、上表の値・照合結果・単位・照合不一致の扱い。
- 特定：依頼文の解析、窓の順序、平日のみ、上限、曖昧な会社名、訂正報告書の確認。
- 候補と反映：出典・連結区分、業種・セグメントの未取得、入力済みの保護、年度ごとの上書き、同じ値の扱い。
- zip・文字コード：圧縮と無圧縮、UTF-16（BOM付き）、壊れた zip の扱い。
- 入口（API）：停止、認証、入力不正、所属・役割・戦略の不一致、依頼の不明、鍵なし、特定の結果（曖昧・未発見・上限）、成功、訂正の採用、取得失敗（再試行しない）。
- 画面：候補の取得で入力が変わらない、承認で反映、入力済みの保護、企業切替で反映しない、曖昧な会社名の表示、チャットからの候補。
- チャット：依頼はAIに送らず候補を作る。

## 9. 残課題

1. **業種（東証33業種）と事業セグメント（名称・金額）の取得**：構造化データからの取り出し方を別途設計する。現状は未入力のまま。
2. **営業利益の4期以前**：この書類には2期分しかない。過去の書類（前期以前の有価証券報告書）を読む拡張が必要。
3. **実ブラウザでの確認**：入力欄の承認までの一連の流れ（ログイン、依頼、候補、承認、反映）は、実環境では未実施。
   実行すると監査ログが本番の監査テーブルに書き込まれるため、本番ではなく検証用の環境で行う。
4. **訂正報告書の確認範囲**：提出後45日の範囲のみ確認する。それ以降の訂正は見つからない可能性がある。
5. **会社名の検索**：提出が集中する月の窓で見つからない会社は、証券コードでの指定が必要（上限150日）。
