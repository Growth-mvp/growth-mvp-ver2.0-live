# Stage 6: 業績シミュレーション

## 目的
Stage 3〜5で定義・運用しているプロジェクト／OKRが、業績（PL等）にどれだけ影響するかを試算します。前提条件を置いた上で複数シナリオ（楽観／基本／悲観）を比較し、計画の妥当性（どの前提が効いているか・どこが弱いか）を数字で検証します。

## ユーザーがやること（最小）
1. **前提を入力**：単価・数量・継続率、原価率、固定費／変動費、投資額、効果発現タイミングなど  
2. **シナリオを設定**：楽観／基本／悲観で前提値を変える  
3. **感度分析**：重要前提を±10%などで動かし、利益・ROIC等がどれだけ動くか確認  
4. **計画前後を比較**：現状（Stage1の実績）と、計画反映後の見通しを比較して意思決定材料にする

## 進め方（UI名に依存しない公式説明）
- シミュレーションは「前提 → シナリオ → 結果確認 → 感度/比較」の順で見ます。
- 結果は少なくとも **売上・利益（営業利益等）・利益率・ROIC等** の変化として確認します。
- 不確実性が高い前提（例：新規獲得数、継続率、原価率）を優先して感度を当てます。

## 出力（得られるもの）
- **3シナリオの業績見通し**（売上・利益・ROIC等の比較）
- **重要前提の影響度**（何を動かすと結果が最も変わるか）
- **計画の妥当性の論点**（前提が弱い／インパクトが薄い／追加施策が必要 など）

## よくある詰まり（対処）
### 「前提値が分からない」
- まずはレンジで置く（例：継続率60〜80%）→感度分析で“効く前提”を特定→その前提だけ精度を上げる。

### 「複数プロジェクトで見積もりが難しい」
- まずは主要プロジェクトから入力し、残りは後で追加する（最初から全部を精密化しない）。

### 「計画と見通しがズレる」
- 影響が出ていない前提（数量／単価／効果タイミング等）が原因になりやすい。前提の置き方を見直し、必要ならStage4/5側の計画や運用も調整する。

## Stage 5 との関係（断言しない）
Stage 5 の進捗ログや実績が揃ってくるほど、Stage 6 の見立ては更新・再評価しやすくなります（具体的な自動連動の有無は実装に依存）。
