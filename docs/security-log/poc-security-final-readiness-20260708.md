- [ ] API 動作確認（クロステナント境界が有効）

### PoC 期間中の制限事項

#### **ユーザー権限制限**
- PoC 参加企業数: 最大 2〜3 社
- ユーザー数: 1 社あたり最大 10 名
- デフォルト権限: member（admin は顧客指定のみ）

#### **機能制限**
- Excel インポート: 試行的機能（admin のみ利用可）
- AI 生成: 標準的な入力値のみ（極端なケースは未テスト）
- データ保持: PoC 終了時に全削除対応（customer-guide.md に記載）

#### **リスク対策**
- **xlsx 脆弱性**: ファイルサイズ制限 10MB、社内資料のみ（外部ファイル禁止）
- **プロンプトインジェクション**: 入力値の事前サニタイズ、生成結果の人的レビュー
- **ログ監視**: 日次で エラー・異常アクセス を確認、インシデント時は即座に連絡

## Ⅳ. 残リスク

### 高リスク項目（本運用前に対応必須）

#### **1. Excel インポート（xlsx ライブラリ）**
- **脆弱性**: Prototype Pollution + ReDoS（CVE 記載）
- **PoC 影響**: 低（admin のみ、社内資料限定）
- **本運用対応**: 3 ヶ月以内に exceljs へ移行
- **現在の対策**: アクセス制限、ファイル制限、サイズ上限 10MB

#### **2. 招待フロー（link-invited-user の暫定設計）**
- **リスク**: 未受諾 invite の メール照合が必須（現在実装済み）
- **本運用対応**: フェーズ 4 で招待トークン方式に統一
- **現在の対策**: メール正規化照合（大文字小文字・空白を normalize）、403 応答

#### **3. 監査ログ未整備**
- **対象**: delete-all・admin 操作・RLS 境界通過試行
- **PoC 対応**: beforeState 取得・audit log に記録（E-07 実装）
- **本運用対応**: ログ保持期間・分析体制を整備

#### **4. CI ゲート未構築**
- **対象**: RBAC E2E テスト、RLS ポリシーテスト
- **PoC 対応**: 範囲限定（主要 API のみ手動テスト）
- **本運用対応**: GitHub Actions で自動化

### 中リスク項目（PoC 後に対応）

#### **5. プロンプトインジェクション耐性**
- **現状**: 文脈乱れで検出（完全防御は未実装）
- **対策**: 生成結果を必ず人間が確認
- **本運用対応**: Prompt engineering + 継続監視

#### **6. RLS ポリシーの動的テスト未実施**
- **対象**: クロステナント READ/WRITE 拒否
- **PoC テスト**: 主要 API の curl テストで確認
- **本運用**: 自動テストに統合

## Ⅴ. 運用上の制限

### PoC 期間中の運用ルール

#### **セキュリティ監視**
1. **日次確認**（朝）
   - 昨日のエラーログ確認（特に RLS・認証・API 403 エラー）
   - 異常アクセス（レート制限超過）の有無

2. **インシデント対応**（24 時間以内）
   - セキュリティ関連エラーが発生した場合、顧客に即座に連絡
   - 詳細を `docs/security-log/incident-20260708-xx.md` に記録
   - 本番 DB への緊急アクション（削除等）は原則禁止（ログ先行）

#### **データ取り扱い**
- PoC データは暗号化されて Supabase に保存（at-rest 暗号化）
- データ送信は TLS 1.2 以上（in-transit）
- 顧客データの国外送信: OpenAI/Anthropic API へのコンテキスト送信
  - お客様デリバティブ（要約・分析結果）のみ
  - 元のテキスト本文は未送信

#### **ログ管理**
- API リクエスト・レスポンスは最小 30 日保持
- メール・会話本文は保持しない（maskEmail・truncate）
- audit_logs への記録: 本人確認・delete-all・role change のみ

#### **定期レビュー**
- **週 1 回**（木）: 顧客からの機能要望・セキュリティ懸念を聴取
- **PoC 終了 1 週間前**: 全データ削除テスト、ロールバック手順確認
