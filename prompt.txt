## ✅ 実装完了（2026-07-03）

空入力ガードの実装は今回は見送ります。
生成を止める処理は入れないでください。

代わりに、まずは安全な観測ログだけ追加・確認してください。

目的：
- 入力が少ない状態でOpenAIが呼ばれていないかを把握する
- ただし、STAGE2の12問未入力やSTAGE3の6問未入力でも、上流データがあれば生成できる柔軟性は壊さない

対応方針：
1. insufficient_input による 400 ブロックは実装しない
2. 既存の生成挙動は変えない
3. OpenAI呼び出し直前に、入力充足度のdebugログだけ出す
4. prompt本文や機密情報はログに出さない

ログ項目：
- requestId
- apiName
- companyId先頭8文字
- strategyId先頭8文字
- meaningfulInputScore
- hasCompanyInfo
- hasStage1Context
- hasStage2Answers
- hasStage2Story
- hasStage3Context
- hasStage4Context
- promptLength
- suspiciousKeywordFlags
  - 自動車
  - 排ガス
  - セラミック
  - OEM

重要：
- このログは本番で過剰に出さない
- NODE_ENV !== 'production' または DEBUG_STAGE_INPUT_GUARD=1 のときだけ出す
- 本文全文は絶対にログ出力しない

対象API：
- stage2/generate-draft
- stage2/generate-final
- stage3/generate-strategy-bridge
- org-alignment/generate
- ask-ceo-agent

今回は「止める」のではなく「見える化」だけにしてください。

## 実装内容サマリー

### 【新ユーティリティ作成】
- lib/inputGuardLogger.ts
  * logInputGuard(): 入力充足度ログ出力関数
  * checkSuspiciousKeywords(): 疑わしいキーワード検出関数
  * 環境制御: NODE_ENV==='production' && DEBUG_STAGE_INPUT_GUARD!=='1' → ログ出力なし

### 【5つの生成APIに統合】
- stage2/generate-draft
- stage2/generate-final
- stage3/generate-strategy-bridge
- org-alignment/generate
- ask-ceo-agent

各APIでOpenAI呼び出し直前に以下をログ出力：

**ログ項目：**
```
{
  '[input-guard]': true,
  requestId: string,
  apiName: string,
  companyId: string (先頭8文字),
  strategyId: string (先頭8文字),
  meaningfulInputScore: number (0-100),
  dataAvailability: {
    hasCompanyInfo: boolean,
    hasStage1Context: boolean,
    hasStage2Answers: boolean,
    hasStage2Story: boolean,
    hasStage3Context: boolean,
    hasStage4Context: boolean,
  },
  promptLength: number,
  suspiciousKeywords: {
    autoMotive: boolean,    // 自動車
    exhaust: boolean,       // 排ガス
    ceramic: boolean,       // セラミック
    oem: boolean,           // OEM
  }
}
```

### 【実装の特徴】
✅ ブロック処理なし（生成は続行）
✅ 観測ログのみ出力
✅ 既存の生成挙動に変化なし
✅ 本文全文はログに出さない（セキュリティ）
✅ 本番環境では制限可能（DEBUG_STAGE_INPUT_GUARD）

### 【目的】
- 入力が少ない状態でOpenAIが呼ばれていないかを把握
- STAGE別データ有無を可視化
- 上流データからの組み立てがどう機能しているかを分析
