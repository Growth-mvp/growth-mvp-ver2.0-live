修正後、今度はSTAGE2→STAGE3ブリッジの完全版が生成・反映されなくなっています。

## 現象
STAGE3上段は表示されていますが、consoleでは以下になっています。

- `[STAGE3 bridge render] summary source`
- `hasStrategicCore: false`
- `concreteDomains: undefined`
- `nonNegotiableThemes: undefined`

つまり、`stage3_strategy_bridge.strategicCore` がstoreに存在していません。

画面も旧4項目の簡略表示に戻っています。
「STAGE3で保持する戦略の芯」も表示されていません。

## 重要
前回の修正で、save guardやnormalize処理を入れた結果、
ブリッジ生成APIの結果がstore/DBに正しく反映されなくなった可能性があります。

## 至急確認してほしいこと

### 1. `/api/stage3/generate-strategy-bridge` が実際に呼ばれているか
Networkまたはconsoleで確認してください。

確認ログを追加：
```ts
console.log('[STAGE3 bridge generate] request start');
console.log('[STAGE3 bridge generate] response', {
  hasBridge: !!bridgeResult,
  keys: bridgeResult ? Object.keys(bridgeResult) : [],
  hasStrategicCore: !!bridgeResult?.strategicCore,
  concreteDomains: bridgeResult?.strategicCore?.concreteDomains,
  nonNegotiableThemes: bridgeResult?.strategicCore?.nonNegotiableThemes,
});
2. APIレスポンスが完全版か確認

期待値：

{
  keyThemes,
  departmentIssues,
  kpiCriteria,
  commonBehaviorChanges,
  strategicCore,
  departmentTranslationRules,
  generatedAt
}

もしAPIレスポンスに strategicCore がないなら、app/api/stage3/generate-strategy-bridge/route.ts 側の問題です。

もしAPIレスポンスにはあるのに画面に出ないなら、app/cascade/page.tsx または store/strategyStore.ts 側で落ちています。

3. 生成結果をstoreに反映する処理を確認

STAGE2→STAGE3遷移時、または「全社戦略サマリーを生成」時に、以下が必ず実行されるようにしてください。

useStrategyStore.setState({
  stage3_strategy_bridge: bridgeResult,
});

その直後に確認ログ：

console.log('[STAGE3 bridge store set]', {
  hasStrategicCore: !!bridgeResult?.strategicCore,
  keys: bridgeResult ? Object.keys(bridgeResult) : [],
});
4. save guardが新規生成をブロックしていないか確認

前回入れた可能性のある以下のようなguardが、新規生成時までブロックしていないか確認してください。

悪い例：

if (existingBridge?.strategicCore && payload.stage3_strategy_bridge && !payload.stage3_strategy_bridge.strategicCore) {
  payload.stage3_strategy_bridge = existingBridge;
}

このguard自体は必要ですが、以下を守ってください。

新規生成された bridgeResult.strategicCore がある場合は絶対にブロックしない
payload.stage3_strategy_bridge が完全版ならそのまま保存する
payload.stage3_strategy_bridge がundefinedの場合に、旧fallback bridgeを勝手に作らない
strategicCoreなしの旧bridgeで、完全版bridgeを上書きしない
5. 旧fallback表示を「生成済み」と扱わない

現在、stage3_strategy_bridge がない/不完全でも、旧4項目のfallbackで上段が表示されているように見えます。

これはデバッグを難しくしています。

一時的に以下のようにしてください。

const hasCompleteBridge = !!stage3_strategy_bridge?.strategicCore;

console.log('[STAGE3 bridge completeness]', {
  hasBridge: !!stage3_strategy_bridge,
  hasCompleteBridge,
  keys: stage3_strategy_bridge ? Object.keys(stage3_strategy_bridge) : [],
});

hasCompleteBridge === false の場合は、旧4項目表示に逃がさず、
「STAGE2からの全社戦略サマリーが未生成です」と分かる状態にしてください。
少なくとも、旧fallback表示を完全版ブリッジとして扱わないでください。

修正のゴール

以下がすべて成立すること。

ブリッジ生成APIが呼ばれる
APIレスポンスに strategicCore が含まれる
storeの stage3_strategy_bridge.strategicCore が true になる
保存payloadにも strategicCore が含まれる
Supabaseの stage3_strategy_bridge.strategicCore が保存される
リロード後も hasStrategicCore: true
「STAGE3で保持する戦略の芯」が表示される
注意

今回の問題は、単にリロード復元だけではありません。
現在は、生成結果が完全版bridgeとしてstore/DBに入っていません。

まず、生成API → store反映 → save payload → DB保存 → hydrate の順にログで追って、どこで strategicCore が消えるか特定してください。


いまの状態は、**「戻る」問題から「完全版bridgeが作られない/反映されない」問題に悪化**しています。  
なのでClaudeには、いったん **APIレスポンス → store set → save payload** の順番で、`strategicCore` がどこで消えるか追わせるのがよいです。
