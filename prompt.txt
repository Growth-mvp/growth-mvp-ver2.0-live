### パターンA
`[DB verify saved bridge] hasStrategicCore: false` の場合：

DB update payloadには入っているのに、実DB保存結果から消えています。
この場合は、`.update(updatePayload)` に渡す直前の payload と、実際に `.select()` で返ってくる `stage3_strategy_bridge` を比較してください。

パターンB

[DB verify saved bridge] hasStrategicCore: true の場合：

DBには保存できています。
その場合、リロード時の fetch / normalize / hydrate で落ちています。

特に、DB rowからstoreへ戻す時に以下のような旧形式再構成をしていないか確認してください。

悪い例：

追加で重要

リロード直後に以下のログが出ています。

[STAGE3 bridge save payload]
hasStrategicCore: false
bridgeKeys: Array(5)

これは、リロード後に不完全bridgeをautosave/manual saveして、DBの完全版を上書きしている可能性があります。

したがって、保存ガードを強化してください。

保存ガードの必須条件

DBまたは直前storeに complete bridge が存在する場合、strategicCoreなしの bridge を保存してはいけません。

if (
  payload.stage3_strategy_bridge &&
  !payload.stage3_strategy_bridge.strategicCore
) {
  const currentBridge = get().stage3_strategy_bridge;

  if (currentBridge?.strategicCore) {
    console.warn('[STAGE3 bridge save guard] blocked incomplete bridge overwrite');
    payload.stage3_strategy_bridge = currentBridge;
  } else {
    console.warn('[STAGE3 bridge save guard] removing incomplete bridge from payload');
    delete payload.stage3_strategy_bridge;
  }
}

重要：
strategicCore なしの stage3_strategy_bridge をDBに保存しないでください。
旧形式 Array(5) bridge は、complete bridge を破壊するため危険です。

完了条件

もし出る場合、その保存はブロックしてください。

重要

今は DB update final payload までは成功しています。
次は必ず [DB verify saved bridge] を展開し、

DB保存で消えているのか
DB保存後のfetch/hydrateで消えているのか
リロード後のautosaveが旧形式で上書きしているのか

この3点を切り分けて、該当箇所を修正してください。
