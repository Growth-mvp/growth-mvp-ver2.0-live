しかし直後に：

- `[STAGE3 bridge restore after save]`
  - `payloadBridge hasStrategicCore: true`
  - `storeNow hasBridge: true`
  - `storeNow hasStrategicCore: false`
  - `storeNow bridge keys: Array(5)`

## 結論
原因は、保存後のstore復元処理です。

`payloadBridge` または `serverData.stage3_strategy_bridge` には完全版bridgeがあるのに、
保存後にstoreへ戻す時点で、旧形式の `stage3_strategy_bridge` が残る、または上書きされています。

## 修正対象
ログ上ではおそらく `store/strategyStore.ts` の以下周辺です。

- `[STAGE3 bridge restore after save]` を出している箇所
- save完了後に `set(...)` / `setState(...)` / normalize結果をstoreへ戻している箇所
- `serverData` をstoreに反映する処理
- manual save / autosave 完了後の restore 処理

## 修正方針

保存後にstoreへ戻す `stage3_strategy_bridge` は、必ず完全版を優先してください。

優先順位：

1. `payload.stage3_strategy_bridge` に `strategicCore` があるなら、それをstoreへ戻す
2. なければ `serverData.stage3_strategy_bridge` に `strategicCore` があるなら、それをstoreへ戻す
3. どちらにもない場合だけ、既存storeのbridgeを維持
4. strategicCoreなしの旧形式bridgeで、完全版bridgeを上書きしない

例：

```ts
const payloadBridge = payload?.stage3_strategy_bridge;
const serverBridge = serverData?.stage3_strategy_bridge;
const currentBridge = get().stage3_strategy_bridge;

const bridgeToRestore =
  payloadBridge?.strategicCore
    ? payloadBridge
    : serverBridge?.strategicCore
      ? serverBridge
      : currentBridge?.strategicCore
        ? currentBridge
        : serverBridge ?? payloadBridge ?? currentBridge;

set((state) => ({
  ...state,
  // 他の保存後反映項目
  stage3_strategy_bridge: bridgeToRestore,
}));

または、保存後に別のnormalize済みデータをstoreへ反映しているなら、最後に必ず以下で上書きしてください。

if (bridgeToRestore?.strategicCore) {
  useStrategyStore.setState({
    stage3_strategy_bridge: bridgeToRestore,
  });
}
絶対に避けること

以下のような旧形式復元をしないでください。

stage3_strategy_bridge: {
  keyThemes,
  departmentIssues,
  kpiCriteria,
  commonBehaviorChanges,
  generatedAt,
}

また、保存後に normalizeFromDbRow(serverData) を使う場合、その結果が旧形式bridgeなら、完全版の payloadBridge を優先してマージしてください。
